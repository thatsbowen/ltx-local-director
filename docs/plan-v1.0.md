# LTX 本地导演台 — 方案 v1.0

> 纯本地、离线、数据不出机的 Windows AI 视频导演台
> 基于 LTX-2.5（22B distilled）本地推理，生成带音频视频

状态：**v1.0 已实现，Phase 0a 实测通过；IC-LoRA 特效待验证**
最后更新：2026-11-09

---

## 1. 产品定位

一句话：**解压即用、全程离线、数据不出本机的 AI 视频导演台。**

- 不做云端 API，不做账号体系，不做遥测
- 唯一联网行为：用户主动发起的模型下载（可完全跳过，改用离线导入）
- 数据目录、缓存、素材全部落在程序目录内，卸载 = 删目录

平台：Windows 10 / 11 x64
（Win10 仅保证 RTX 30/40 系；RTX 50 系建议 Win11）

### 3.2 方案 A：Fork 官方 LTX Desktop

验证清单（30 分钟，必须先做）：

1. 仓库是否公开，许可证是否允许 fork + 改名 + 闭源分发 + 接受打赏
2. 技术栈（Electron / Tauri / PyQt）— 若 PyQt，React UI 资产作废
3. 是否已封装 ltx-pipelines 推理调度与模型管理（fork 的唯一高价值点）
4. 是否支持 NVFP4 / 低显存串行加载
5. 是否内置遥测或云 API（需剥离）

### 3.3 方案 B：从零 + 复用现有壳

复用 `minimax-h3-director`：

- 现成：便携打包、免安装、托盘、`app://` 协议、Zustand 状态、打赏页
- 改造：`src/main/minimax.ts` → `ltxEngine.ts`（Python 子进程）
- 改造：`Studio.tsx` / `PromptComposer.tsx` / `GenerationSettings.tsx`

**建议：能 fork 就 fork 引擎层 + 复用现有 UI 壳（混合方案）；不能 fork 整体走 Plan B。**

## 4. 量化档位与硬件引导

### 4.1 显存预算

```
总显存 ≈ Transformer + 文本编码器（串行时可省） + VAE + 激活 + 解码峰值 + 1.5G 余量
```

| 组件 | BF16 | FP8 | INT8 | Q5 | Q4 | Q3 |
|---|---|---|---|---|---|---|
| Transformer 22B | 44G | 22G | 22G | 15.5G | 13G | 10.5G |
| Gemma4 12B | 24G | 12G | 12G | 9G | 7G | 5.5G |
| 视频 VAE | 1–2G | — | — | — | — | — |
| 激活 + 解码峰值 | 5–10G（随分辨率） | | | | | |

**关键结论：≤32GB 必须串行加载。** 文本编码器与 transformer 不同时驻留：
加载 Gemma → 编码 → 释放 → 加载 transformer → 去噪 → 释放 → tiled VAE 解码。

### 4.2 五档推荐

| 档位 | 量化组合 | 分辨率 × 时长 | 速度（估） | 模型下载量 | 结论 |
|---|---|---|---|---|---|
| 8GB | GGUF Q3 + 全 offload | 768×448 × 3s | 15–40 min | ~12 GB | 实验性，强提示 |
| 16GB | NVFP4(50系) / INT8(40系) + Gemma 跑 CPU | 960×544 × 5s | **1.5–2 min**（2.3 实测，2.5 待测） | ~24 GB | 主力档 |
| 24GB | NVFP4 全驻留 / FP8(Ada) | 1216×704 × 6s | 2–4 min | ~26 GB | 甜点 |
| 32GB | FP8 全驻留 + 2× 放大 | 1080p × 6–10s | 1.5–3 min | ~40 GB | 推荐 |
| 64GB | BF16 全精度 + DFR | 1080p × 10s+ | 1–2 min | ~85 GB | 最佳画质 |

### 4.3 硬约束（必须写进引导）

- **NVFP4 仅 Blackwell（RTX 50 系, sm_120）**，40/30 系不显示该选项
- **FP8 需 Ada 及以上（sm_89+）**，3090 不支持，检测须读 compute capability
- **tiled VAE decode 默认开启**，否则 720p 解码阶段必 OOM
- **RTX 50 系 + Win10** 驱动支持有限，需黄条提示建议升级 Win11

### 4.4 引导流程

1. 硬件自检：`nvidia-smi --query-gpu=name,memory.total,compute_cap,driver_version` + 内存 + 磁盘 + CUDA 版本
2. 自动匹配档位 → 推荐方案卡（模型、下载量、分辨率、速度、限制）
3. 手动切换档位（高级）：高于硬件 → 黄条警告；低于硬件 → 画质损失提示
4. 首跑基准测试（480p / 3s）→ 记录峰值显存与耗时 → OOM 或超时自动降档

## 5. 分发与模型获取

### 5.1 程序包

```
LTX-Local-Director-v1.0-Win64.7z.001 / .002   ≈ 4GB
└── 解压即用
    ├── LTX-Local-Director.exe
    ├── runtime\      Python 3.12 + PyTorch CUDA（~4GB）
    ├── engine\       推理引擎
    ├── data\         用户数据（任务 / 素材 / 设置）
    └── 使用说明.txt
```

- 不写注册表、不写 AppData，卸载 = 删目录
- 2GB/卷，方便小水管

### 5.2 模型获取（两选一）

**A. 应用内下载**（唯一联网入口，用户主动点击）

- 断点续传、国内镜像、分文件 sha256 校验
- 失败精确提示：「第 3 个文件损坏，请重下」

**B. 离线导入**

- 选文件夹 / U 盘，支持从另一台机器拷贝
- 目录结构校验后自动识别档位

### 5.3 模型清单（16GB 档）

| 文件 | 体积 |
|---|---|
| transformer 22B · NVFP4 | 12 GB |
| gemma4-12b · Q5 GGUF | 9 GB |
| video VAE · bf16 | 1.5 GB |
| audio VAE · bf16 | 0.3 GB |
| IC-LoRA × 2 | 1.5 GB |
| **合计** | **~24.3 GB** |

磁盘需求：程序 4GB + 模型 24GB + 工作缓存 10GB ≈ **38GB 空闲**

## 6. 功能范围

| v1 做 | v1.1+ 再做 |
|---|---|
| 文生视频（T2V） | 多关键帧（>2 帧） |
| 单图生视频（I2V） | 2× 空间放大（16GB 档硬件不支持） |
| 首尾帧（FLF 单阶段，输出=基础分辨率） | 自由视频重绘 |
| V2V：2 个 IC-LoRA 固定特效 + 二次确认 | 自定义 LoRA 导入 |
| 音频默认开启 | 音频单独编辑 |
| 提示词助手（可选 LLM） | 云 API 兜底（与定位冲突，不做） |

### 6.1 IC-LoRA 特效

| 特效 | 状态 | 风险 |
|---|---|---|
| 线稿动画 | 已定 | 低，风格类 LoRA 常见 |
| 景深强化 | 待验证 | 若是 depth control LoRA，需额外集成深度估计模型（~1GB）+ 改管线；不可用则替换为第二个风格类特效 |

> **v1.0 实现说明**：界面保留「特效转换」入口并标注「即将开放」，点击只提示、不切换模式；
> 主进程 `validateRequest` 与 `buildWorkflow` 同样拦截该模式。待 19B IC-LoRA 与 22B
> 主模型的兼容性验证通过后，再开放并补充 `buildEffect` 工作流。

## 7. 提示词系统

按 LTX 官方结构：

- 单段连贯文字、4–8 句、200 词内、现在时
- 对白加引号
- 顺序：镜头 → 场景 → 动作 → 角色 → 镜头运动 → 声音 → 风格 → 约束
- 多镜头 2–4 个

UI 提供：结构模板、实时体检（长度/句数/要素缺失）、正向/负向提示词分离。

### 7.1 助手 LLM

- 默认：Qwen3-4B-Instruct Q4_K_M ≈ 2.5GB
- 低配：Qwen3-1.7B Q4 ≈ 1.1GB
- llama.cpp 独立进程，**生成前自动卸载**（16GB 显存无法与 12GB transformer 共存）
- 用途：改写/扩写提示词，不参与生成

## 8. 隐私与离线保障

| 场景 | 联网 |
|---|---|
| 生成视频 / 音频 | 强制拦截 |
| 提示词助手 | 全本地 |
| 模型下载 | 仅用户主动点击 |
| 遥测 / 自动更新 | 不存在 |

工程落地：

- 主进程不引入任何 HTTP 客户端
- `session.defaultSession.webRequest` 拦截一切非 `file://` / `app://` 请求
- 应用内「网络活动」面板，实时显示被拦截请求数（正常恒为 0）
- 打赏二维码为本地静态图，不触发网络

## 9. Phase 0 验证清单

环境：Win11 + 最新驱动 + CUDA 12.8+ + Python 3.12，RTX 5060 Ti 16GB

1. 跑通原生 fp8-cast（基线，验证链路）
2. 跑通 NVFP4（目标路径，确认 ComfyUI NVFP4 kernel 在 sm_120 正常）
3. 四组基准：`480p/3s`、`544p/5s`、`704p/5s`、`704p/6s`
4. 每组记录：峰值显存、耗时、OOM、音频正常性、音画同步
5. 对比 Gemma 在 CPU vs GPU 的串行加载耗时
6. 测 tiled VAE decode 阈值
7. 确认「景深强化」是否有 LTX-2.5 可用权重
8. 产出 `bench-5060ti.md`，反推默认参数与引导文案真实数字

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 官方 LTX Desktop 不可 fork | 架构决策失效 | 走 Plan B（复用现有壳） |
| 景深 LoRA 不存在 | v1 少一个特效 | 替换为第二个风格类特效 |
| NVFP4 在 sm_120 上 kernel 不稳 | 16GB 档不可用 | 回退 INT8 + block-swap |
| 16GB 跑 704p 仍 OOM | 分辨率上限下调 | 默认 544p，704p 标为「尝试」 |
| Win10 + 50 系驱动缺失 | 部分用户跑不起来 | 首启黄条提示升级 Win11 |
| 24GB 跑 720p/6s 未实测 | 文案可能虚高 | Phase 0 校准后再定稿 |
