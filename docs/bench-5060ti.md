# Phase 0a 基准 — RTX 5060 Ti 16GB

采集时间：2026-11-08
**注意：本轮使用 LTX-2.3（distilled Q4_K_S GGUF），不是 2.5。**
数据用于验证引擎链路与量级，2.5 需重测。

## 3. 关键发现

### 3.1 sigma 调度决定画质，不是模型问题

用 `0.85, 0.725, 0.4219, 0.0`（4 步）跑**基座阶段**会产生覆盖全画面的规则网格伪影。
该调度只适用于**第二阶段精修**；基座必须用 `1.0, 0.99375, …, 0.0`（9 步）。

**这是引擎实现里最容易踩的坑，必须在代码里写死校验。**

### 3.2 显存始终贴着上限，与分辨率弱相关

所有配置峰值都在 15.3–15.7 GB（可用 15.9 GB）。
说明 ComfyUI 在做动态 offload，实际是「用时间换显存」，而不是「小分辨率就省显存」。

含义：
- 不能靠「降分辨率」来给其他功能腾显存
- 余量只有 200–600 MB，任何额外常驻模型都会 OOM

### 3.3 分辨率比时长更贵

| 对比 | 耗时 |
|---|---|
| 960×544 / 5s | 85.8s |
| 1216×704 / 4s | 110.1s |

像素量增加 64%，耗时增加 28%；时长增加 25%，耗时只增加 12%。
**优化优先级：先控分辨率，再控时长。**

### 3.4 音频

- 流存在：AAC 48 kHz 立体声，与视频同轨封装正常
- 环境声 prompt：mean −49.5 dB / max −28.6 dB（偏轻）
- 台词 prompt 测试见 §4

### 3.5 I2V 比 T2V 贵一倍

| 模式 | 配置 | 耗时 |
|---|---|---|
| T2V | 960×544 / 4s | 76.4s |
| I2V | 960×544 / 4s | **153.8s** |

多出的开销来自：输入图 VAE 编码 + `LTXVImgToVideoInplace` 的 guide 注入。
**UI 的耗时预估必须按模式区分，不能共用一套数字。**

### 3.6 首尾帧的接线陷阱

首次尝试在 `LTXVCropGuides` 报错：

```
'NestedTensor' object has no attribute 'clone'
```

原因：AV 合并后的 latent 是 NestedTensor，不能直接裁剪。正确顺序是：

```
SamplerCustomAdvanced.denoised_output(槽位 1)
  → LTXVSeparateAVLatent
      ├─ 槽位 0 → LTXVCropGuides → VAEDecodeTiled
      └─ 槽位 1 → LTXVAudioVAEDecode
```

另外两个容易踩的点：

- 采样结果必须取 **`denoised_output`（slot 1）**，不是 `output`（slot 0）
- 模板的 guide 顺序是**先加尾帧（frame_idx=-1）、再加首帧（frame_idx=0）**

修正后：**85.6s / 15.2 GB / 首尾帧均命中**。
首尾帧比 I2V 还快（85.6s vs 153.8s），因为 guide 是零成本注入，不像 I2V 需要整图编码。

注意：当首尾帧主体完全无关时，末帧边缘会出现残影（测试用了两张不同人像）。
真实场景首尾同主体不会出现，但 UI 仍应提示「首尾帧主体差异过大会产生变形」。

## 4. 音频台词测试

Prompt：*"A young man sits at a wooden desk … and says: \"Hello, this is a local AI video test.\""*

| 指标 | 值 |
|---|---|
| 耗时 | 104.0s |
| 峰值显存 | 15.7 GB |
| mean volume | **−17.4 dB** |
| max volume | **−0.2 dB** |

**结论：音频分支正常，语音清晰、电平健康。**

上一轮环境声只有 −49.5 dB，是 prompt 本身要求「轻柔鸟鸣」导致的，不是模型缺陷。
这意味着引擎需要提供「**音频强度 / 是否含对白**」的显式选项，否则用户会误以为音频坏了。

画面抽样帧显示人物口型张开、与台词同步，说明音画对齐正常。

## 5. 对 16GB 档的结论

| 项 | 结论 |
|---|---|
| 默认配置 | **960×544 / 4–5s / 9 步** → 76–86s |
| 上限配置 | **1216×704 / 4s** → 110s |
| 冷启动 | +70s |
| 显存余量 | 200–600 MB，无冗余 |

**相比方案初稿估算的「4–8 分钟」，实测快 3–5 倍。**
但这是 2.3 + Q4_K_S 的结果；2.5 + NVFP4 需要重测后才能定稿对外文案。

### 5.1 建议的引擎默认值（16GB 档）

| 参数 | 默认 | 说明 |
|---|---|---|
| 分辨率 | 960×544 | 1216×704 作为「高质量」可选项 |
| 时长 | 4s（97 帧） | 5s 仅 +12% 耗时，可放宽 |
| 帧率 | 24 | 与 LTX 原生一致 |
| 步数 | 9 | 基座必须 9 步，4 步仅用于精修 |
| cfg | 1.0 | 蒸馏模型 |
| 采样器 | euler | |
| VAE 解码 | tiled 512/64 | 必开 |
| 音频 | 默认开 | 需提供强度/对白选项 |
| 首条预热 | 提示 +70s | UI 必须显示，否则用户以为卡死 |
